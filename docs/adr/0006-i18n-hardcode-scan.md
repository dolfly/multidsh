# 0006. i18n 硬编码文案由扫描测试守护

- 状态：已采纳
- 日期：2026-09（i18n-coverage.test.ts 落地）

## 背景

应用只做 zh/en 双语，文案集中定义在 `src/shared/i18n/messages.ts`。风险是新代码图省事把中日韩文案直接写进组件或主进程错误消息——编译器不报错、界面看起来也「能用」，但语言切到 en 后这些字符串原样残留，且事后翻找极难（分布在几百个文件里）。

## 决策

`src/renderer/src/i18n-coverage.test.ts` 扫描整个 `src/` 树的 `.ts`/`.tsx`/`.css`/`.html`：

- 逐行检测硬编码 CJK 文案（保留字符串、模板、正则、JSX/HTML 文本节点的语义边界；注释等长抹除以保持行号）；
- 违规站点必须**显式登记**在两份清单之一（用户可见待迁移 / 内部诊断），清单与扫描结果集合相等——多出的登记、漏登记的新站点都会让测试变红；
- 主进程日志（`console.*` 实参）豁免：日志只进终端，不面向用户。

## 后果

- 新增硬编码文案在 `pnpm test` 时立即暴露，登记清单就是待办清单；
- 代价：扫描器本身约 1.7k 行，需与 TS/JSX 语法演进保持同步——集中在一个测试文件里，可控。

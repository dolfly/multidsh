# DSH Hub v0.1.5

- 发布日期： 2026-10-19
- 标签： `v0.1.5`

## 分发方式

- `windows-unsigned`

## 产物

- `DSH-Hub-Setup-0.1.5.exe`（Windows x64 NSIS 安装包，未签名）
- `SHA256SUMS.txt`（上述安装包的 SHA-256 校验清单）

> 安装包未经代码签名，Windows 首次运行会出现 SmartScreen「未知发布者」提示——点「更多信息 → 仍要运行」即可继续。下载后请用 `SHA256SUMS.txt` 校验完整性。macOS 暂不提供官方二进制，仍需从源码构建。

## 概述

本版本把插件安装与升级做成「先看清、再执行」的完整闭环：安装改为两步——先解析出确切版本、发布时间、近 30 天下载与 dsh 兼容性，确认后才下发 `name@x.y.z`；升级二次确认支持切换 npm 安装源（解析与升级强制同源），版本行改为「旧版 → 新版」，并回显插件名防止升错对象。同时修复了 hub 与 dsh 对「替换已装包是否需要重启」的判定分歧：HMR 可用时热生效，不再无条件要求重启。设置侧新增「安装镜像」的编辑入口（此前只能在创建向导里设置），插件检查/安装的默认源随之联动。

## 亮点

- **插件安装两步走**：第一步输入插件标识并选定安装源（默认国内镜像），确定后先解析——npm 裸名按「dist-tag latest 与最大稳定版的较大者」选版本（`@latest` 同口径，dist-tag 滞后也装得到新版），显式版本与具名 dist-tag 各按其口径，github:/file: 不联网直接进入确认；第二步确认区给出**插件名 / 版本 / 发布时间 / 近 30 天下载 / dsh 兼容 / 更新内容**（GitHub Release → 仓库 CHANGELOG → 无 逐级降级），不兼容必须勾选风险确认才能提交。安装参数固定为解析出的 `name@x.y.z` 并与解析同源追加 `--registry`，registry 后续发新版不影响本次已确认的选择；「安装后启用」默认勾选，取消则只安装、落在禁用态。
- **升级可切换安装源**：升级二次确认顶部新增安装源选择（npmmirror / npmjs，默认与检查同源）；改选即作废当前计划、按新源重新解析，解析与升级必须同源，档位经 zod 校验的枚举透传到主进程，非法值在 IPC 边界即被拒绝。
- **版本演进行 + 插件名回显**：确认区版本行在已装版本与目标版本不同时渲染「`1.0.0 → 1.1.0`」（旧版弱化在左、目标徽标在右，箭头即说明）；「版本」行之上新增「插件」行回显包名，先看清对象再读版本，避免点错。
- **重启判定与 dsh 同口径**：dsh-hmr 按磁盘身份（inode/size/mtime）判定模块过期并热重载，dsh 自身的 `change()` 只在无 HMR 或 reconcile 报重启原因时才要求重启。hub 此前把「替换已装包」判成无条件需重启（前提「Node 模块缓存无法换模块代」是错的），现 install/upgrade/remove 统一按「实例是否启用热更新」给出 applied / restart-required，重启提示文案改为只解释「该实例未启用热更新」。
- **安装镜像可随时改**：编辑实例对话框新增「安装镜像」四档（跟随系统 npm 配置 / npmmirror / npmjs / 自定义 URL，https 信任根，本地镜像放行回环 http），应用级设置、对所有实例生效；同一设置推导插件命令与安装/升级对话框的**默认安装源**，dsh 下载与插件检查/安装的默认源自此一致。

### 修复与体验

- **插件安装对话框加宽**到与日志浮层同档，版本事实与更新内容一屏读完；「安装后启用」的后果说明收进问号气泡，hover 或键盘聚焦才展开，不再常驻占版面。
- **气泡互斥**：焦点展开改为只认键盘焦点（`:focus-visible`），鼠标点选说明文本后移开即收起，相邻行不会同时弹出两个气泡。
- **检查结果可读性**：行内截断的不兼容/检查失败说明改为 hover 气泡展开完整文案（可聚焦、读屏可读）；检查有更新、不兼容、失败都写入底部信息栏，批量检查按类别各汇总一行。
- **设置页重排**：通用偏好卡的长说明收进标题旁问号图标气泡，分组标题行右侧挂载控件（重新检测、工作区缓存上限）；「刷新环境缓存」改为报告刷新前后的环境差异（只回传 PATH 条目与变量名，变量值可能含凭据、绝不出主进程），toast 按「有变化 / 无变化 / 不可比」三种结果反馈。
- **运行环境卡**：操作按钮上方增加分隔线，升级按钮与版本数据留在线上方，操作区贴底。
- **关于面板**：数据列支持点击复制。
- **插件未发布到 npm**（`pnpm view` 404）时给出明确文案，不再透出裸命令行错误。
- **实例分区放行纯音频采集权限**，dsh web 的语音输入可用。

### 测试与 CI

- 新增 `plugin:resolveInstall` / `plugin:packageInfo` 通道与安装源枚举契约的单测；E2E 覆盖安装两步全流程、升级换源后确认区收回再回来、确认后 `add` 带 `--registry`、版本演进行与插件名行的位置断言。
- 环境 diff 测试按平台显式选 PATH 分隔符（POSIX 夹具传 darwin），修复 Windows CI 上整串 PATH 被当成单条目的失败。
- 「刷新环境缓存」补基线/冷缓存单测与「出结果 toast、不弹重启确认」的 E2E。

## 从源码构建

需要 Node 22+、pnpm，以及目标平台对应的构建环境：

```bash
pnpm install
pnpm build
pnpm test
pnpm dist:win        # Windows 本地构建（Windows 上）
# 或 pnpm dist:win:local   # mac 上交叉构建 Windows 包
# 或 pnpm dist:mac   # macOS 本地构建（未签名 .app，仅本机验证）
```

本地构建生成的产物未签名、未公证；macOS 产物仅适用于开发、本机验证或受控测试，不随发布上传。

## 当前限制

- Windows 安装包未签名，首次运行会触发 SmartScreen 提示；macOS 不提供官方二进制，需从源码构建。
- 插件自定义安装源只支持两档预设（npmmirror / npmjs）；镜像地址里的自定义 registry 作用于 dsh 下载，插件命令的默认源按两档预设映射，其余地址回落默认档。
- 首次创建本地实例可能需要联网准备 dsh 运行时；内网环境可设置 `DSH_HUB_NPM_REGISTRY` 或在编辑实例中改安装镜像。
- 版本检查仅覆盖 hub 托管的本地实例；SSH / 远程实例暂无获取其 dsh 版本的途径。镜像 `latest` 标签滞后于新发布时，以版本列表最大值为准。

Windows 代码签名与 macOS 二进制分发的门槛见 [发布策略](https://github.com/xbzbing/dsh-hub-desktop/blob/main/docs/release-policy.md)。

# DSH Hub v0.1.6

- 发布日期： 2026-10-25
- 标签： `v0.1.6`

## 分发方式

- `windows-unsigned`

## 产物

- `DSH-Hub-Setup-0.1.6.exe`（Windows x64 NSIS 安装包，未签名）
- `SHA256SUMS.txt`（上述安装包的 SHA-256 校验清单）

> 安装包未经代码签名，Windows 首次运行会出现 SmartScreen「未知发布者」提示——点「更多信息 → 仍要运行」即可继续。下载后请用 `SHA256SUMS.txt` 校验完整性。macOS 暂不提供官方二进制，仍需从源码构建。

## 概述

本版本把「当前运行的 app 用了什么、风险在哪」摆到台面上：「关于」面板新增第三方依赖清单，只列真正打包进产物的 62 个包（按 main / preload / renderer 三个构建产物汇总，含实际安装版本），可就地展开查看、区块内独立滚动。插件升级确认框里的更新内容不再按纯文本显示——GitHub Release 与 CHANGELOG 本就是 Markdown，现按 dsh 同款 micromark/mdast 生态渲染成受净化的 React 元素，原始 HTML 一律不执行。同时完成两条安全升级：Electron 44→45（Chromium 152→156、Node 24.21→24.22，修复 2 条安全通告）与 zod 4.6.5→4.6.7（修复 1 条高危原型污染通告）。

## 亮点

- **关于面板第三方依赖清单**：「关于」对话框新增可折叠的第三方依赖区块——只列**打包进构建产物**的包（构建期由 rollup 钩子扫描三个 target 的 chunk 模块清单汇总，版本取 pnpm 实际解析版本），不列开发期工具链；`vitest`、`eslint` 这类纯 devDependency 永不出现。目的是第三方组件爆出安全风险时，用户能在自己的运行包里一眼核对「我是否受影响、影响哪个版本」。默认折叠、展开计数，展开后清单在 150px 的独立区域内滚动，不会把整个对话框撑满；对话框本身加宽 10%（452 → 497px）容纳版本列。
- **插件更新内容按 Markdown 渲染**：升级 / 安装确认框的「更新内容」取自 GitHub Release body 与仓库 CHANGELOG 原文，此前按纯文本显示，标题、列表、表格、代码块全是字面量。现用 mdast-util-from-markdown + GFM 扩展解析为 mdast 树，映射成 React 元素渲染——不生成 HTML 字符串、不走 `dangerouslySetInnerHTML`，正文原始 HTML 一律不执行；链接仅 http(s) / mailto 可点击，`javascript:`、`data:`、`file:` 与相对路径降级为纯文本，外链统一交主进程按协议白名单后交给系统默认程序。确认框同步加宽 10%（560 → 616px）给表格与代码块留横向空间。
- **Electron 45 + zod 4.6.7 安全升级**：Electron 44.4.3 → 45.0.0（Chromium 152.0.7977.130 → 156.0.8078.48、Node 24.21.0 → 24.22.0、V8 15.6），消除 Electron 分发线上的 2 条已知安全通告；zod 4.6.5 → 4.6.7 修复 zod <4.6.6 的原型污染通告（GHSA-mrhx-c7xc-m3w5）。zod 仍是唯一进入产物的运行时依赖，`dependencies` 保持为空由测试守护。

### 修复与体验

- **停止实例按整棵进程树排空**：hub 停止本机实例时 spawn 的是 dush/duush 启动器，包装器收到 SIGTERM 立刻死、其下的 dsh 被 reparent 后仍异步优雅退出（最长 5s）——原实现 2ms 就宣布停止完成，紧随其后的 start 撞端口，且残留 dsh 脱离托管后被外部探测误报为「本机已在运行的 dsh web」。现停止判据改为整棵进程树排空（POSIX 探测进程组存活，上限 6s 后升级强杀；Windows 走 `taskkill /T`），决策见 ADR-0012。
- **外部 dsh 探测按进程树判定**：探测器原先只认旧命令行形态 `dsh web`，当前 CLI 的 `dsh --profile web` 一条都认不出来，向导与详情页的接管入口整块不渲染。现命令行形态与「是否 Hub 托管」拆成两件事：后者按进程树判定并以托管端口兜底；命令行出主进程前脱敏（dsh token 写在命令行上）。多个 dsh 在跑时向导用下拉选择；新增 live 验收脚本防止合成夹具与真实 CLI 形态脱节，决策见 ADR-0011。
- **stderr 凭据脱敏**：插件命令与运行时安装失败的错误消息取自 npm stderr 尾部、会经 IPC 到达界面 toast——补上键值凭据形态（`npmToken=xxx` / `password=xxx`）的脱敏，与既有的 URL 查询串脱敏并列，失败原因本身保留。
- **插件详情加名称行**：确认与详情区新增可复制的插件名行，操作行的 GitHub 图标移除。
- **关于面板**：数据列沿用点击复制；对话框宽度加宽后版本信息与依赖清单列不再拥挤。

### 测试与 CI

- **半自动发布链路**（ADR-0008）：新增 `release:publish` 脚本——按序推 tag、建/更新 Draft、上传资产并做白名单核验，`--publish` 才正式发布，每步幂等可重跑；`release:check` 离线演练发布说明与打包配置。
- **E2E 数据目录隔离**（ADR-0009）：用例数据统一经 `e2eDataDir` / `e2eEnv` 注入仓库内 `hub-data/e2e-*` 并加静态守卫，真实用户数据目录不再有被测试触碰的可能。
- **架构护栏**：ESLint 分层规则（`src/shared` 等不得 import Electron）、IPC 通道四面对账（contracts/register/bridge/preload 漏同步即红）、发布文档本地路径引用检查；ADR 0001–0012 与发布 runbook 入库。
- **大规模模块拆分**：plugin-manager、register 测试、store、传输与运行时、ssh-tunnel、local-runtime、i18n 扫描、共享契约、npm 调用层按职责拆成独立单元并抽共享 testkit，单测 1585 项、E2E 63 项全绿。
- **开发依赖大版本升级**：ESLint 10（react-hooks 7）、Vitest 5、electron-vite 6、npm 12、@types/node 26，其余仅跟 patch/minor；dependabot 改为 devDependencies 分组并忽略 major。

## 从源码构建

需要 Node 22+、pnpm，以及目标平台对应的构建环境：

```bash
pnpm install
pnpm build
pnpm test
pnpm dist:win        # Windows 本地构建（Windows 上）
# 或 pnpm dist:win:local   # mac 上交叉构建 Windows 包
# 或 pnpm dist:mac   # macOS 本地构建（未签名 .app，仅本机验证）
```

本地构建生成的产物未签名、未公证；macOS 产物仅适用于开发、本机验证或受控测试，不随发布上传。

## 当前限制

- Windows 安装包未签名，首次运行会触发 SmartScreen 提示；macOS 不提供官方二进制，需从源码构建。
- 第三方依赖清单只覆盖打包进产物的包；`out/` 未完整构建时（如全新克隆后仅 `pnpm dev`）该区块不显示。
- 插件更新内容只渲染 Markdown 正文，不执行任何内嵌 HTML；表格样式随系统原生排版。
- 外部 dsh 探测依赖进程树与托管端口，包装器先退出且 dsh 被 init 收养的极端形态以端口兜底。
- 版本检查仅覆盖 hub 托管的本地实例；SSH / 远程实例暂无获取其 dsh 版本的途径。

Windows 代码签名与 macOS 二进制分发的门槛见 [发布策略](https://github.com/xbzbing/dsh-hub-desktop/blob/main/docs/release-policy.md)。

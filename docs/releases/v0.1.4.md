# DSH Hub v0.1.4

- 发布日期： 2026-10-13
- 标签： `v0.1.4`

## 分发方式

- `windows-unsigned`

## 产物

- `DSH-Hub-Setup-0.1.4.exe`（Windows x64 NSIS 安装包，未签名）
- `SHA256SUMS.txt`（上述安装包的 SHA-256 校验清单）

> 安装包未经代码签名，Windows 首次运行会出现 SmartScreen「未知发布者」提示——点「更多信息 → 仍要运行」即可继续。下载后请用 `SHA256SUMS.txt` 校验完整性。macOS 暂不提供官方二进制，仍需从源码构建。

## 概述

本版本是焦点行为的修补版本：修掉三条会把 DSH Hub 窗口顶到前台、抢走其它应用（如如流）焦点的路径，让「正在别的应用里操作，DSH 突然跳到最前」不再复现；同时修掉插件卡三处信息显示错误（兼容范围显示为空、升级提示过期、发布时间缺失），并在「关于」面板补上构建 commit 与打包时间。

## 亮点

- **前台抢焦点：三条路径修复**（承接 0.1.3 已生效的后台闸门，本轮修的是前台路径）：
  - `app.on('activate')` 只在没有任何可见窗口时（最小化到托盘 / 窗口已销毁）才召回窗口，窗口已可见时不再 `show()+focus()`。这是日志坐实的主路径：activate 可能由非用户操作触发，而真正的 Dock 点击由 macOS 自行把应用带回前台，不需要我们再置前一次。
  - `focusEntry` 的延迟聚焦在回调真正执行时**再次**校验窗口是否仍聚焦：从调度到执行之间用户若已切走，放弃本次聚焦，不再把窗口抢回前台。
  - 宿主窗口失焦后跳过工作区悬停提示。提示窗是浮动子窗口，对它在后台调用 `showInactive` 时，这个置前请求会被 macOS 挂起数秒后再批准，把整个应用顶回前台；现在只在宿主窗口聚焦时显示提示。
- **关于面板展示构建信息**：构建期把 git 短 hash 与打包时刻注入主进程 bundle（运行时不再触碰 git），「关于」面板在版本号下方新增「构建版本 / 打包时间」两行，打包时间按本地时区展示，便于一眼确认当前运行包的来源与新鲜度。无 `.git` 或 git 不可用时回落 `unknown`。

### 修复

- **插件「兼容版本」显示为空**：dsh 兼容范围此前只读主包 `@deepseek-ai/dsh` 的 peer，而插件普遍只声明若干锁步同版本的 `@deepseek-ai/dsh-*` 子包（如 `dsh-skill`、`dsh-tools`），主包为空就渲染成「dsh —」。现按「主包优先，否则取各子包的公共范围」派生，升级不兼容提示同步受益，不再出现没有信息量的「要求 dsh —」。
- **插件升级提示过期**：持久化的检查记录缺少「检查时的已装版本」，渲染层只用候选版本是否等于已装版本来判断「已升级过」；当已装版本**高于**记录中的候选（手动安装、降级等绕过 hub 升级流程的变化）时该判定失效——已装 1.1.17 仍提示「新版 1.1.15 要求 dsh … 不满足」。现记录绑定检查时的已装版本，版本一变旧结果即失效；更早版本写入的记录因无法校验是否仍适用，在读取时丢弃。同时「是否有更新」改用版本序比较，已装版本高于镜像 `latest` 时不再误报。
- **插件发布时间缺失**：`dsh plugin view <name> time --json` 只查 `time` 单字段时返回的是裸的「版本 → 发布时刻」映射，多字段查询才嵌套在 `time` 键下；此前只按嵌套形状解析，导致详情页线上必现「点检查升级获取」。现两种形状都兼容。

### 测试与 CI

- 向导「等待外部 dsh」用例覆盖 Windows 最坏预算（PowerShell 15s + netstat 10s = 25s），单轮等待放宽到 30s，并在仍不出现时关掉向导重开触发新一轮扫描（此时 CIM 已热），修复 Windows CI 上的偶发超时。
- E2E 隐藏模式放行悬停提示窗的前台守卫，恢复提示窗样式用例。
- 新增焦点排查日志：`win.blur`、`shell.openExternal` 三个入口、`app.activate`、guest `webContents` 获焦，用于区分「DSH 主动让出焦点」与「被其它应用抢占」。

## 从源码构建

需要 Node 22+、pnpm，以及目标平台对应的构建环境：

```bash
pnpm install
pnpm build
pnpm test
pnpm dist:win        # Windows 本地构建（Windows 上）
# 或 bash docs/local/build-win-local.sh  # mac 上交叉构建 Windows 包
# 或 pnpm dist:mac   # macOS 本地构建（未签名 .app，仅本机验证）
```

本地构建生成的产物未签名、未公证；macOS 产物仅适用于开发、本机验证或受控测试，不随发布上传。

## 当前限制

- Windows 安装包未签名，首次运行会触发 SmartScreen 提示；macOS 不提供官方二进制，需从源码构建。
- 焦点行为依赖对 macOS 前台/后台事件的观察，相关日志仅在排查时启用。
- 首次创建本地实例可能需要联网准备 dsh 运行时；内网环境可设置 `DSH_HUB_NPM_REGISTRY`。
- 版本检查仅覆盖 hub 托管的本地实例；SSH / 远程实例暂无获取其 dsh 版本的途径。镜像 `latest` 标签滞后于新发布时，以版本列表最大值为准。

Windows 代码签名与 macOS 二进制分发的门槛见 [发布策略](https://github.com/xbzbing/dsh-hub-desktop/blob/main/docs/release-policy.md)。
